# 城市地下管网养护管理平台

面向市政供排水、燃气、供热、电力管线等地下管网的普查建档、巡检养护、病害修复、开挖审批与应急抢修的综合管理后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 管沟风险判定口径

管沟风险在采集（登记/更新）、展示（列表/明细/导出/看板）、处置（疏排积水/更换盖板/
强制通风）三个阶段共用同一份判定逻辑，统一收在
`backend/app/services/trench_risk.py`，任何视图都不得自行计算等级。

- 输入：一条管沟记录的 `积水情况`、`气体浓度`、`盖板完好`、`沟内管线` 与
  处置动作写入的因子级覆盖（`处置覆盖`）；字段可缺，缺失按保守口径处理。
- 输出：`风险等级`（高/中/低）、逐因子结论与总体理由（`风险说明`/`风险判定`）、
  `rule_version`、待补字段清单、采纳/作废的处置记录。
- 阈值（临界值归高一档）：积水 `>=40cm` 高风险、`>0` 中风险；气体 `>=25%LEL`
  高风险、`>0` 中风险；盖板「缺失」高、「破损」中、「完好」低；沟内燃气/高压热力
  等管线把后果权重抬到中风险。总体取各因子最严档；任一关键因子缺失则至少中风险。
- 缺失数据：空值或无法解析的文本判中风险并在理由中注明待补字段，结论确定、可复现。
- 处置与复测：处置只在因子级记录「已处置、待复测」的覆盖；该因子一旦采集新值
  （即使数值与处置前相同），旧处置即粘性作废并按新观测重判；规则版本升级后，
  旧记录缓存的等级在任一展示出口惰性重算，保证各视图结论一致且可解释。
- 相关接口：`GET /api/trench` 支持 `risk_level` 筛选，`GET /api/trench/risk-summary`
  返回风险分布，`PUT /api/trench/{id}` 更新观测字段并即时重判。
